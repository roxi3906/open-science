## 命名边界

既有环境变量名称保留。仅形似环境变量的错误码、远程探测输出、R 路径探测和批处理分隔标记已统一新名称，生成端、解析端和测试样本一起更新。用于表达授权状态的业务枚举、资源 ID 和用户保存的正文不按品牌字符串重写。

## 中断恢复与限制

桌面身份日志按 `prepared → key-ready → profile-ready → complete` 推进。数据根搬迁复用存储迁移标记和清理日志；只有源、目标清单都与验证结果一致，才能提交新指针。未确认退出的旧内核或 Shell 进程会阻止迁移，不能假定 Electron 退出后所有子进程也已结束。

迁移保留用户文件正文、已发布签名内容、数据库历史校验和、Conda 安装历史及既有业务 ID。这些是历史证据和兼容输入；修改它们可能破坏签名、追溯关系或用户内容。旧名称不得用于新的业务对象。

**中断恢复不等于版本回退。** 当前日志支持向前继续迁移。密钥身份和资料目录提交后，不能仅换回旧应用二进制：旧版可能重新创建旧资料及密钥，造成加密数据无法读取。正式升级前应在应用和子进程停止后保存一致的配置、数据库、桌面资料及数据根快照，并验证恢复步骤。需要回退时必须协调恢复密钥身份、资料目录、数据库账本、设置格式和启动器；本分支尚无经过跨平台验证的自动反向迁移，不支持把二进制降级当作回退方案。

不能可靠重定位的自定义运行环境会中止搬迁并保留原环境。未完成的运行环境操作须先恢复。远程主机上的用户激活脚本不能仅按目录名推断所有权，也不能在运行任务尚未退出时移动其工作目录。未知的顶层用户文件会留在源目录，不递归删除源根目录。运行环境内部绝对符号链接会重定位并验证，指向外部的链接会阻止提交。已完成迁移的桌面资料目录随后丢失时会报告错误，不静默创建空资料。

## 尚未完成的发布条件

1. **Windows AppContainer / WFP 实机验证。** 当前所有权根、AppContainer 前缀与新 WFP 标签已统一为新品牌，x64/arm64 程序已交叉重建并同步 SHA-256。显式安装先对旧收据执行原生所有权验证和可重试的资源清理，取消或失败时不创建新资源；显式卸载及 NSIS 卸载处理两代收据。旧 WFP 标签仅由已验证的旧 profile 身份选择，原互斥量与新互斥量按固定顺序同时持有以防旧进程竞态。迁移拒绝符号链接目录，不以路径名称代替安装 ID、SID、所有权令牌和过滤器 GUID 验证。真实 Windows 上的 UAC、ACL、网络阻断、崩溃恢复和卸载尚未执行，交叉编译及适配器测试不能代替这些运行证据。
2. **旧版 CLI 先于 GUI 启动。** 已发布 v1 启动器硬编码旧可执行文件路径；文件被更新器移除后，它无法运行应用内的自修复代码。必须先发布桥接版本，或提供在替换旧文件前执行的安装器迁移入口。它需验证受管启动器、写入最终路径并验证目标，再允许替换旧应用；最终版本不保留旧名称的永久别名。当前分支仅实现启动后的受管修复，不能宣称这条升级路径已完成。
3. **Linux 凭据库实测。** 对 Secret Service、KWallet 和无安全后端环境分别验证旧密文读取、新密文重启读取、锁定和双条目冲突；禁止遇到迁移失败就重建凭据或降级明文。
4. **外部发布身份。** 检查时 `aipoch/open-science-specialist-marketplace` 返回 404，现有仓库为 `aipoch/openscience-specialist-marketplace`。需先迁移拥有的仓库、原始文件地址、发布流程和 CDN，再切换客户端地址。已发布签名键 ID `openscience-marketplace-2026-08` 和 SignPath 已签发证书主体不能靠字符串替换重命名；需新签名元数据或重新签发，并保留历史验证链。
5. **远程遗留文件退休。** 在每台实际主机上确认旧任务结束、文件已收集，验证用户激活脚本在新路径下行为一致后，再迁移或退休旧目录。代码已支持新写入和旧恢复，未连接、修改任何实际计算主机。
6. **SDK 调用方升级。** SDK 改用 `connect`、`Client`、`ApiError`，属于公开 API 的破坏性变更。调用方须同步更新导入、类型和异常判断，按破坏性变更发布独立版本；不能覆盖已发布包或假定外部脚本会自行迁移。仓库内调用方和类型声明已同步，包内 README 提供旧导出到新导出的迁移表。本次未发布 npm 包。

项目 AGENTS.md 要求连接虚拟机前取得用户明确授权和指定的专用容器名称。本次没有连接虚拟机；Windows 环境授权仍待提供。外部仓库、云端服务、证书和发布配置也未作实际变更。
